# Architecture Decision Log

## D-001: WPF вместо Tauri

**Решение:** C#/.NET 10/WPF.

**Причина:** проект Windows-only и зависит от большого числа маленьких native windows, topmost, click-through, global hotkeys, DPI и Explorer integration. Отдельный Tauri WebView на карточку увеличил бы память и усложнил синхронизацию состояния.

**Следствие:** UI реализуется XAML/C#, а Windows-specific behavior доступен напрямую через HWND/Win32.

## D-002: отдельное окно на карточку

**Решение:** одна карточка — одно WPF window.

**Причина:** прозрачная пустая область единого fullscreen overlay не должна блокировать клики. Небольшие native WPF windows дешевле отдельных WebView и дают простой rectangular hit area.

**Следствие:** нужен централизованный `CardWindowManager` и аккуратный lifecycle.

## D-003: два глобальных режима

**Решение:** все карточки одновременно находятся в Edit либо Focus mode.

**Причина:** отдельный lock на каждой карточке создаёт ситуацию, когда click-through окно нельзя вернуть мышью. Глобальный hotkey всегда обеспечивает выход.

## D-004: SQLite с первого прототипа

**Решение:** `Microsoft.Data.Sqlite`, не JSON settings file.

**Причина:** карточки являются изменяемыми сущностями; SQLite даёт атомарность, миграции и простое дальнейшее расширение.

## D-005: ограниченные типы карточек

**Решение:** Task, Note, Image.

**Причина:** этого достаточно для проверки ценности. Timer добавляет отдельную state machine и восстановление времени, не проверяя основной window hypothesis.

## D-006: локальные ссылки на изображения

**Решение:** для выбранного или перетащенного файла хранить исходный absolute path. Bitmap, полученный напрямую из clipboard без стабильного исходного файла, сохранять как уникальный PNG в `%LOCALAPPDATA%\FocusOverlay\images`.

**Причина:** файловый reference не дублируется, а clipboard bitmap получает устойчивый путь и переживает перезапуск приложения.

**Следствие:** удалённый или перемещённый файл отображается placeholder; карточка остаётся редактируемой/удаляемой.

## D-007: self-contained publish без installer

**Решение:** выпускать папку через `dotnet publish -r win-x64 --self-contained true`.

**Причина:** её достаточно для локального прототипа. Installer, signing и auto-update откладываются.
